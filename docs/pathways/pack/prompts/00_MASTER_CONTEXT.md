## Product
Pathways is an Education Pathways Ecosystem, not an online school at launch. It helps parents explore alternatives, creates a useful preliminary Discovery Report, and offers an appropriate next conversation. It is K-12 capable with grades 5-12 as the initial marketing emphasis.

MVP journey: marketing homepage -> age/grade-appropriate parent profile -> deterministic exploratory directions -> honest personalized Discovery Report -> optional verified save -> available consultation workflow -> small advisor workspace.

Future paid Blueprints and ongoing services may be explained as future/available only according to configuration. The future Pathways Mastery School is not available, not recommended, and never the default when generic matching returns little information. There are no named provider placements in Discovery V1.

## Nonnegotiable behavior
1. The same effective answers and versions produce the same underlying recommendations. Student names, contact details, lead source, timeline, referral economics and willingness to buy do not change educational fit.
2. Use canonical registries. A pathway is a base model plus overlays, possible supports, opportunities and review items. Do not conflate a service with a school.
3. At least two independent supported dimensions must justify a displayed candidate; baseline score alone is insufficient. One or zero cards is valid. Unknown is not no. Public reports never display percentages or Strong Potential Fit in this release.
4. K-4 has developmental context, adult availability and foundational learning. No K-4 credit, NCAA or college pressure. Do not infer academic readiness, actual supervision or local eligibility from interests.
5. Provide the useful guest report without a mandatory email/account wall. Saving is optional and verified. Separate requested delivery from marketing permission. No mandatory phone number for email saving.
6. The report contains recognition, one meaningful insight, credible directions, relevant opportunities, important questions, a preliminary pathway sketch and an available CTA. No fear, guilt, fake scarcity, fabricated testimonials, hours-saved claims, guaranteed placements or school authority.
7. Deliver complete reports using templates before adding optional AI. AI may only personalize summary and insight from approved minimal facts. It cannot choose pathways, investigate providers or generate consequential academic conclusions.
8. Protect child/family information from the first persistence layer. Enforce record-level authorization on every read, write, action and export. Parent A must not access Parent B's record even with its exact ID. Advisors see authorized assigned cases only. Keep internal scores and notes out of public API responses.
9. No real email, booking, AI request, child-data collection or production deployment until the relevant operational and privacy gates pass. Unconfigured features return honest unavailable/request states; do not fake success.
10. Each phase includes tests, traceability and actual completion evidence. A compilation pass alone is not feature acceptance.

## Implementation preference
Use the existing sound stack if present. For a new custom app, propose Next.js App Router, TypeScript, PostgreSQL, a typed migration layer, schema validation, accessible components and unit/E2E tests. One modular app, no unnecessary microservices or vector database. Select current supported versions by checking official documentation and the actual repository; pin the working versions. Google sign-in is optional. Use a supported established auth solution, not bespoke authentication.

Design the data model around a Student Pathway Record, but implement only guest session, profile revisions, engine runs, reports, guardian access, consent, consultation workflow and staff notes now. Do not build the whole future platform.
